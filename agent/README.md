# 아크덴트 EMR(덴트웹) 중계 프로그램

치과의 덴트웹 DB에서 **오늘 수납액 · 내원 · 신환/구환 · 예약** 숫자를 읽어서
아크덴트(Supabase)로 보내는 프로그램입니다.

```
[덴트웹 DB] → [중계 프로그램 (치과 PC)] → [Supabase] → [아크덴트 홈 화면]
                     ↑ 서버 IP·전송 간격은 관리자모드 "EMR 연동"에서 원격으로 받아옴
                     ↓ 동작 상태(정상/오류)를 관리자모드에 보고
```

- 덴트웹 DB는 **읽기만** 합니다. (덴트웹이 외부 연동용으로 공개한 뷰/프로시저만 사용)
- 홈 화면용으로는 합계 숫자만 보냅니다.
- 상담일지 환자 검색·접수현황용으로 **최근 30일 환자 명단**(차트번호, 이름, 출생연도, 성별, 등록/내원일, 접수 시각·상태·담당의)만 보내고 30일이 지나면 지웁니다. **연락처·주민번호·주소는 보내지 않습니다.**
- SQL Server는 덴트웹에 원래 들어 있으므로 따로 설치하지 않습니다. 필요한 건 **Node.js**뿐입니다.

## 설정 정보는 어디에?

| 정보 | 위치 |
|---|---|
| 덴트웹 서버 IP · 포트 · 인스턴스 · 전송 간격 · 연동 켜기/끄기 | **관리자모드 → EMR 연동** (원격 수정 가능) |
| Supabase 주소·키 (모든 치과 공통) | `defaults.json` — 다른 치과 설치 때 같이 복사 |
| 중계 계정, 덴트웹 아이디/비밀번호 | `config.json` — 이 치과 PC에만 보관, **절대 복사 금지** |

> 덴트웹 비밀번호는 환자정보 조회 권한이 있어서, 인터넷(Supabase)에 모아두지 않고 각 치과 PC에만 둡니다.

## 새 치과 설치 순서 (약 20분)

### 0. Supabase: 치과 등록 (처음 한 번)
SQL Editor에서 실행 (code는 영문 소문자, 예: `hclinic`)

```sql
insert into public.clinics (name, code) values ('○○치과', 'hclinic');
```

### 1. 관리자모드: 계정 만들기
**관리자모드 → 계정 관리** 에서 그 치과를 선택
- **[중계 계정]** → 만들기 → 나온 이메일·비밀번호를 setup.bat 에 넣을 때까지 보관 (창을 닫으면 다시 볼 수 없음 → 잊으면 비밀번호 버튼으로 새로 만들기)
- 원장님 / 병원관리자 계정도 여기서 만들기

### 2. 관리자모드: EMR 연동 설정
**관리자모드 → EMR 연동** 에서 그 치과를 선택하고 입력 후 저장
- 서버 IP: 중계 프로그램을 **덴트웹 서버 PC에 설치하면 `127.0.0.1`**, 다른 PC면 서버 PC IP
- 포트: 보통 `1436`

### 3. 치과 PC: 설치
1. **Node.js LTS** 설치: <https://nodejs.org>
2. 이 `agent` 폴더를 그 PC에 복사 (예: `C:\arcdent-agent`)
   - ✅ `defaults.json`은 **같이 복사** (Supabase 주소/키를 다시 묻지 않음)
   - ❌ `config.json`, `state.json`, `logs`, `node_modules`는 **빼고** 복사
     (`config.json` = 다른 치과 비밀번호, `state.json` = 다른 치과 진행 기록)
3. **`setup.bat`** 더블클릭 → 질문에 답하기
   ```
   중계 계정 이메일: bclinic-agent@arcdent.local
   중계 계정 비밀번호: (입력해도 화면에 안 보임)
   덴트웹 외부연동 아이디: …
   덴트웹 외부연동 비밀번호: (입력해도 화면에 안 보임)
   ✅ 아크덴트 로그인 성공 — 대상 치과: ○○치과   ← 치과가 맞는지 꼭 확인!
   ✅ 덴트웹 접속 성공
   ```

### 4. 점검 → 전송 → 자동 실행
1. **`check.bat`** → 숫자를 덴트웹 일일 마감과 비교
2. **`send-once.bat`** → 아크덴트 홈 화면 확인
3. **`install-task.bat` → 마우스 오른쪽 → 관리자 권한으로 실행**
4. 관리자모드 → EMR 연동에서 그 치과가 **🟢 정상**인지 확인

## 자동 업데이트

치과 PC에서 업데이트를 따로 할 필요가 없습니다.

- 자동 실행되는 것은 **런처(`launcher.js`)**이고, 런처가 실제 중계 프로그램을 켜고 관리합니다.
- 런처는 30분마다 `https://arcdent.vercel.app/agent/manifest.json`에서 새 버전을 확인합니다.
- 새 버전이 있으면 내려받아 **파일 지문(sha256)을 검증**한 뒤 교체하고 재시작합니다.
- 새 버전이 시작하자마자 3번 연속 꺼지면 **이전 버전으로 자동 복구**하고, 그 버전은 다시 받지 않습니다.
- `config.json`, `defaults.json`, `state.json`, `logs`는 업데이트 때 절대 바뀌지 않습니다.
- 버전은 관리자모드 → EMR 연동의 "설치 PC" 칸에서 확인할 수 있습니다.

개발자: `agent/package.json`의 `version`을 올려서 main에 push하면, Vercel 빌드 때 `scripts/build-agent-bundle.mjs`가 묶음을 만들고 모든 치과가 30분 안에 업데이트됩니다.

## 지난 데이터

- 매 전송 때 오늘 일별 기록과 이번 시간 누적 기록("어제 이 시간까지" 비교용)을 저장합니다.
- 처음 설치하면 최근 13개월 기록을 **전송 주기마다 한 달씩** 덴트웹에서 다시 계산해 채웁니다. (약 40분)
- 매일 밤 최근 7일을 다시 계산해서 늦게 들어온 수정·환불을 반영합니다.
- 진행 상황은 `state.json`에 저장됩니다.

## 관리자모드 "EMR 연동" 상태 보는 법

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 🟢 정상 | 최근 전송 성공 | - |
| 🟠 오류 | 프로그램은 켜져 있지만 덴트웹 접속 등 실패 | 내용 칸의 메시지 확인 |
| 🔴 연결 끊김 | 보고가 끊김 | PC 전원·인터넷·자동 실행 확인 |
| 설치 대기 / 미설정 / 중지 | 아직 설치 전, 또는 연동 꺼둠 | - |

서버 IP를 바꾸거나 연동을 끄면 **다음 전송 때(몇 분 안에) 자동 적용**됩니다.

## 문제 해결

| 메시지 | 확인할 것 |
|---|---|
| `Failed to connect` | 관리자모드의 서버 IP/포트. 다른 PC면 서버 PC 방화벽 1436 포트 허용 |
| `Login failed` | 덴트웹 아이디/비밀번호 → `setup.bat` 다시 실행 |
| `Supabase 로그인 실패` | 중계 계정 이메일/비밀번호, Auto Confirm |
| `agent로 등록되어 있지 않습니다` | 1단계 SQL 실행 여부 |
| `덴트웹 서버 주소가 없습니다` | 관리자모드 → EMR 연동에 서버 IP 입력 |
| `'chcp'은(는) ... 아닙니다` | `agent` 폴더를 최신으로 다시 복사 |

설정을 바꾸려면 언제든 `setup.bat`을 다시 실행하면 됩니다. (비밀번호 칸은 Enter만 누르면 기존 값 유지)
작업 기록은 `logs` 폴더에 날짜별로 남고 14일 후 자동 삭제됩니다. (숫자만 기록, 개인정보 없음)

## 개발자용

```bash
npm test        # 집계 로직 자체 테스트 (덴트웹 없이)
npm run setup   # 대화형 설정
npm run check   # 점검 모드
npm run once    # 1회 전송
npm start       # 실행 모드
```

- 실제 접속 설정 = 관리자모드 설정(서버/포트/인스턴스/DB) + `config.json`(아이디/비밀번호). 관리자모드에 서버가 없으면 `config.json`의 서버 값 사용.
- 홈 화면이 읽는 payload 형태는 `src/aggregate.js`의 `buildPayload`와 `src/components/home/HomeLiveSection.jsx`가 맞춰져 있어야 합니다.
- Supabase 테이블: `supabase_live_dashboard.sql`, `supabase_emr_settings.sql`
